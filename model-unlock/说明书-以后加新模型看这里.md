# 说明书：以后官方发布新模型，照这个做

> 适用：锁死不升级的旧版 Antigravity（真实 1.20.6，装在 `D:\Antigravity`），zk 插件 **≥ 9.9.530**，zk 模式保持默认 `custom`。
> 覆盖：Google Gemini 3.9 / 4.0 / 4.1…、Anthropic Claude 5.6 / 5.7 / 5.8… 等任何官方新模型。
> 原理手册见仓库根目录 `SOP-新模型放行.md`；本文件是"下次直接照做"的傻瓜清单。最近更新 2026-10-04。

---

## 0. 先记住三句话（避免白忙）

1. **下拉里自动出现了新模型 ≠ 能用。** 旧语言服务器（LS，2026-03 冻结）把新模型降级成整数 `choice.value=0`；在下拉里选中任何"官方新项"，前端都会回退上报成默认 `gemini-3.8-flash-high`，**界面选新款、实际还在跑 3.8**。新模型必须加成"带 `__agUid` 的合成项"（Gemini、Claude 都一样）。
2. **uid 必须逐字照抄官方，不能按版本号猜。** 例如中档后缀是全称 `-medium`，写成 `-med` 直接 HTTP 404；未来命名规律也可能变。
3. **后端 zk 通用透传任意 uid，同代新模型只改前端一张表、零改后端。** 只有"新模型缺必需字段报 400"或"官方跨大版本改协议"才需要动后端（见第 5 步）。

> 一句话：**任何新模型都不会零操作自动可用；按下面 6 步走，约 10–20 分钟。**

---

## 1. 拿到官方真实 uid（最关键的一步）

真实 uid（如 `claude-sonnet-5-5-high`、`gemini-3.8-flash-high`）只存在于官方 `fetchAvailableModels` 原始响应里；前端内存（clientModelConfigs）和下拉 DOM 里只有显示名和整数，**拿不到 uid**。用本目录的护栏脚本临时把这份响应落盘：

```powershell
# 在 compat-manager 仓库根目录执行

# (1) 干跑自检（只读，不改任何东西）。期望看到"锚点正常"。
node model-unlock/capture-official-catalog.mjs check

# (2) 安装临时落盘探针（自动备份 source.js.agcap.bak；写入后 node --check，失败自动回滚）
node model-unlock/capture-official-catalog.mjs install

# (3) 彻底关闭 IDE：任务管理器确认 Antigravity.exe = 0、language_server = 0
#     （或直接借 .\放行Claude六档.ps1 -ForceKill 的关进程能力，但先别让它打补丁也行）

# (4) 双击桌面彩色 Antigravity 图标启动，等 10–30 秒让模型列表刷新

# (5) 探针已把官方目录写到运行态扩展目录（<最新版本> 取版本号最高的那个）：
#     C:\Users\Administrator\.antigravity\extensions\zk-agent.zk-proxy-pro-<最新版本>\
#       vendor\bundled-origin\_agcap\_ag-models-catalog.json
Copy-Item "<上面那个 _ag-models-catalog.json>" "model-unlock\fetchAvailableModels.json" -Force

# (6) 立即撤销临时探针（务必！别让探针长期留在运行态）
node model-unlock/capture-official-catalog.mjs restore

# (7) 列出官方全部 Claude / Gemini 的真实 uid
node model-unlock/list-official-uids.mjs
```

从第 (7) 步输出里，找到目标新型号的**完整 uid**（high/medium/low 各是独立 uid）和它的官方显示名。

**辅助 / 兜底途径：**
- 若手上已有 zk 诊断日志 `_ea_diag.log` 且其中含完整 `OFFICIAL-BODY-HEX`（默认只截前 500 字节，需曾专门放大），可用 `node model-unlock/decode-official-models.mjs <_ea_diag.log 路径>` 解（一般用不上，走上面的护栏脚本即可）。
- 现有 `model-unlock/fetchAvailableModels.json` 是 **2026-10-04** 快照，当时官方最新只到 **Gemini 3.8 / Claude 5.5**；更新的模型不在里面，必须按上面流程重新抓。

## 2. 在唯一映射表加行

打开 `model-unlock/patch-workbench.mjs`，顶部 `const MODELS = [ … ]` 是**唯一前端映射表**，追加：

```js
{ label: '照官方显示名，如 Claude Sonnet 5.6 (High)', uid: '第1步拿到的真实uid' },
```

- 每个档位一行（High/Medium/Low 是三个独立 uid）。
- **Gemini 新模型也要在这里加成合成项**，否则即使下拉自动出现，选中也会回退 3.8（见第 0 节第 1 句）。
- 所有合成项统一借 `modelAlias:8` 外壳（脚本已固定，勿改；alias:7 会永久挂起）。

## 3. 关 IDE + 一键注入

```powershell
# 彻底关 IDE（ag=0、ls=0）后，在仓库根目录：
pwsh -File .\放行Claude六档.ps1 -ForceKill
```

脚本会：从干净基线还原 workbench → 注入 MODELS → 校验 5 个锚点计数都恰为 1 → `node --check`，**失败自动回滚、绝不留半成品导致 IDE 卡死**。正常应看到 5 个 `anchor count = 1` 和 `SYNTAX OK`。

## 4. 启动 + GUI 验证（必做，不能省）

1. 双击桌面彩色 Antigravity 图标启动；扩展详情版本正常、单窗口不卡死、能登录、**默认仍是 Gemini 3.8 Flash (High)**。
2. 下拉出现新项；选中新模型，发一句 `say ok`，正常流式出字。
3. 看两个硬证据：
   - 落盘文件 `…\zk-agent.zk-proxy-pro-<最新>\vendor\bundled-origin\_agcap\_ag-selected.json` 里 `last.uid` = 你选的新 uid（120 分钟新鲜窗口）。
   - 正常流式出字即网关 200；响应每帧 `modelVersion` = 该 uid（最权威，证明真走的是新模型）。
4. 验完可切回默认 3.8。

## 5. 判断要不要动后端（多数情况不用）

- **同代小版本**（Gemini 3.8→3.9、Claude 5.5→5.6/5.7）：后端**零改动**，compat 对任意 uid 按 `body.model` 透传。
- **新模型报 HTTP 400（缺该版本必需字段）**：在 zk 源码 `plugins/zk-proxy-pro/vendor/bundled-origin/_ag-gemini37-compat.cjs` 按 uid 做通用字段补齐（这是唯一常规需要动后端的情况）。改完跑 `npm test`（当前基线 32 项全过）、`node tools/checks/antigravity-target-check.js`，再按 `SOP` 第五节 bump 版本 + CLI 重装 vsix。
- **跨大版本**（如 Claude 6、Gemini 5）若官方改了网关协议 / 鉴权 / 必需字段：无法保证只改表，需重新抓包按 SOP 第一节原理适配。

## 6. 收尾提交

- **没动后端**（最常见）：只提交 compat-manager —— 更新的 `patch-workbench.mjs`、`fetchAvailableModels.json`、文档。
  ```powershell
  git add -A
  git commit -m "feat(model-unlock): 放行 <新型号>"   # 中文 message 建议用 git commit -F <UTF-8文件>
  git push                                           # 仓库已配代理 127.0.0.1:51081
  ```
- **动了后端**：在 Antigravity-Injection 跑 `node scripts/bump-version.mjs <新版本号>`（自动改版本→build→测试→提交推送），关 IDE 用 `D:\Antigravity\bin\antigravity.cmd --install-extension <dist\新vsix> --force` 安装（自动建新版本目录、旧版进 .obsolete），再把 compat 的 SOP/handoff/rules 版本号同步。
- 更新本文件与 `SOP-新模型放行.md`、`.agents/handoff.md` 里的"当前已放行清单 / 快照日期 / 插件版本"。

## 报错对照表

| 现象 | 真实原因 | 处理 |
|---|---|---|
| 下拉里没有新项 | 没加 MODELS，或前端脚本没跑成功 | 回第 2–3 步；确认 5 个 `anchor count = 1` |
| 选了新款、回复却还是 3.8 | 该项是无 `__agUid` 的官方项，被回退默认 | 必须在 MODELS 加合成项（Gemini 同样）|
| `HTTP 404 Requested entity not found` | uid 拼错（典型：`-med`）| 回第 1 步逐字核对真实 uid |
| 选中后一直 Working / Generating 挂起 | 误用了非 `modelAlias:8` 外壳 | 合成项必须借 alias:8（脚本已固定）|
| `HTTP 400` | 新模型缺必需字段 | 第 5 步，在 compat 按 uid 补字段 |
| 前端脚本报 `ANCHOR CHECK FAILED` | IDE 版本变动致 workbench 5 锚点漂移 | SOP 第四节：重新定位 nKc/dutE/vKc/Kun/I |
| capture 报"锚点计数异常" | zk 插件版本变动致 source.js 锚点漂移 | 见下方"锚点失配" |
| 界面显示某模型、回复却像另一模型 | 上报失败静默回退 3.8 | 查 `_ag-selected.json`；确认 zk 是 custom、8937 在监听 |

## 锚点失配（IDE 或插件升级后）

- **前端 workbench 锚点**：对象是 `D:\Antigravity\resources\app\out\vs\workbench\workbench.desktop.main.js`，按 SOP 第四节在新文件里重新定位 nKc/dutE/vKc/Kun/I 五处（历史逆向脚本在本机 `evidence/`，不入库，换机需重建）。
- **后端 capture 锚点**：在运行态 `source.js` 搜 `_extractModelsFromRPC(fullBody`，把 `capture-official-catalog.mjs` 顶部 `ANCHOR` 三行更新为新文件里的逐字文本（**含缩进**），先 `check` 到计数=1 再 `install`。

## 已验证 vs 推断（信心说明）

- **已端到端实测（信心 10）**：Claude 5.5 六档 uid、Gemini 3.8 high、借 `modelAlias:8` + `/__agtarget` 旁路、统一网关凭 `body.model` uid 路由零转换、落盘与回显链路。
- **capture 抓取脚本**：锚点已在 9.9.530 上用 `check` 只读验证计数=1（信心 9）；探针复用 zk 现成的 2MB 响应缓冲、内联 require、仅被动落盘。但"install→重启→生成 catalog→restore"完整链路**首次尚未实跑**（为保持运行态干净没有真插）；第一次用时按第 1 步走，护栏会在锚点异常/语法失败时自动中止或回滚。
- **同代新模型"只改一张表即可"**：信心 7–8（基于网关通用性的推断，未经未来模型实证）。
- **跨大版本必兼容**：不做保证；官方改协议需重新适配。
